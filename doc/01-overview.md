# 01 — نظرة عامة على النظام

## الهدف

نظام مراسلات رسمية (صادر / وارد) بهوية الجهة، قابل لإعادة الاستخدام عبر إعدادات الاسم والشعار والعنوان. الخطاب غالباً يُكتب في Word؛ النظام يحفظ **بيانات المعاملة** (الرقم، الجهة، التاريخ، QR) ويمكنه **إشعار المستلم** بالبريد أو واتساب.

نظام الدعوات نظام **منفصل** — لا استيراد إعدادات منه وقت التشغيل (يُستفاد منه كمرجع للبنية فقط، مثل النسخ الاحتياطي).

## التقنيات

- PHP (Vanilla) + MySQL (PDO)
- Bootstrap 5 (RTL) + Bootstrap Icons
- SweetAlert2 (تنبيهات وتأكيدات)
- QR Code في الطباعة وصفحة التحقق العامة

## الوحدات الوظيفية

| الوحدة | الوظيفة |
|--------|---------|
| وارد / صادر | ترقيم آلي، مرفقات، حالات، أولوية، طباعة + QR |
| إحالات | تحويل بين الأقسام مع تتبع |
| ربط وارد↔صادر | عند إنشاء صادر كرد على وارد |
| أرشيف | حفظ معاملات مع أنواع أرشفة |
| تقارير | إحصائيات + تصدير CSV |
| إدارة | مستخدمون، أقسام، جهات، قوائم، إعدادات، **نسخ احتياطي**، سجلات |

## دورة الصادر العملية

1. تُعرَّف الجهة في **جهات المراسلة**: الاسم، التكريم (حفظه الله / حفظها الله)، الجوال، البريد.
2. تُنشأ معاملة صادر (مفردة أو جماعية لمجموعة مثل مجلس الأمناء).
3. النظام يعطي كل مستلم **رقماً مستقلاً** و**رمز QR** يشير إلى صفحة التحقق.
4. يُنسخ الرقم وQR إلى خطاب Word إن لزم، أو تُطبع الخطابات من النظام.
5. من صفحة الصادر: **إرسال بالبريد** و/أو **واتساب**، ثم **التسليم والحالة → التسليم** — راجع [09-outgoing-receipt.md](09-outgoing-receipt.md).

## الصادر الجماعي

نفس الموضوع ونص الخطاب لمجموعة مستلمين. لكل عضو:

- رقم صادر خاص
- QR خاص
- رسالة بريد/واتساب خاصة باسمه وتكريمه

لا تُرسل رسالة واحدة للجميع برقم واحد.

## الوارد

الوارد يُسجَّل ويستلم ويُحال داخلياً. الإرسال الإلكتروني (بريد/واتساب) مخصص **للصادر** إلى الجهات الخارجية.

## الصلاحيات

| الدور | الإرسال من الصادر |
|--------|-------------------|
| مدير / أرشيف / قسم | يمكنه الإرسال إذا كانت لديه صلاحية تعديل الصادر |
| مشاهد | عرض فقط |

الإعدادات (SMTP وواتساب) للمدير فقط. تفاصيل الأدوار: [14-roles-and-permissions-guide.md](14-roles-and-permissions-guide.md).
