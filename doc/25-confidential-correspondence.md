## القاعدة الذهبية

| الطبقة | ماذا تتحكم؟ | ماذا لا تفعل؟ |
|--------|-------------|---------------|
| **A — الرؤية** | من يرى المعاملة/وثيقة الأرشيف في القوائم والفتح | لا تتخطّى مراحل المسار |
| **B/C — المرفقات** | من يحمّل الملفات السرية (إعداد عام + تجاوز لكل عنصر) | لا تمنع مخوّل المسار من **فتح** الصفحة |
| **D — استثناءات عليا** | منشئ، مدير، `view.confidential.*`، رافع الملف | لا تُلغى بمفاتيح B/C |
| **المسار (0)** | تفعيل المراحل والإسناد | مستقل عن السرية |

> القسم وحده **لا يكفي** لرؤية السري. التحقق **لحظي** عند كل طلب حسب الوضع الحالي للمستخدم والعنصر.

---

## 1) متى تكون سرية؟

`confidentiality` ≠ `normal` → مقيّدة (`confidentiality_is_restricted()`).

تنطبق على: وارد / صادر / داخلي / أرشيف عام / سجلات المنح والمشاريع والمالية (عمود `confidentiality`).

---

## 2) الطبقة A — من يرى العنصر السري؟

| الطرف | يرى؟ |
|--------|------|
| المنشئ | نعم |
| مخوّل مسار (مراجع/معتمد/اتصالات/موقّع إعداد/للاطلاع حسب الإسناد) | نعم |
| `view.confidential.{type}` | نعم |
| مدير النظام | نعم |
| زميل القسم فقط | **لا** |
| عادي `normal` | كما نطاق القسم اليوم |

**الأرشيف العام:** منشئ / `view.confidential.general` / مدير.  
**السجلات:** منشئ / `view.confidential.{scholarships|projects|finance}` / مدير.

فلاتر القوائم والعدادات تستخدم شروط SQL تقريبية + فحص PHP عند الفتح (`user_can_access_correspondence` / `user_can_access_archive` / `user_can_access_register_row`).

إعداد عام: `confidentiality_restricts_visibility` (افتراضي مفعّل) في إعدادات الصادر/المسار.

---

## 3) الطبقات B / C / D — المرفقات

### B — مفاتيح عامة (افتراضي مسموح)

`conf_attach_prep_signer` · `conf_attach_reviewer` · `conf_attach_approver` · `conf_attach_comms` · `conf_attach_cc`

تعطيل المفتاح = الدور يرى الصفحة ويعمل؛ الملفات مقفلة.

### C — تجاوز لكل عنصر

عمود JSON `confidential_attach_overrides`: لكل دور `inherit` | `allow` | `deny`.  
المنع يغلب عند تعدد الأدوار.

**الواجهة:** بجانب حقل السرية يظهر زر قفل المرفق عند اختيار درجة غير «عادي». القائمة فوق الزر تتيح لكل دور **السماح** أو **الحظر** لهذه المعاملة فقط. إن تُركا فارغين يُتبع إعداد النظام من **إعدادات السرية** (`admin/confidential_settings.php`). ينطبق على الوارد والصادر والداخلي والصادر الجماعي والأرشيف العام وسجلات المنح/المشاريع/المالية.

### D — دائماً يفتحون الملفات (إن رأوا العنصر)

منشئ · مدير · صلاحية سرية النوع · رافع **ذلك** الملف.

الدوال: `user_can_view_corr_files` / `user_can_view_corr_document` · `user_can_view_archive_file` · `user_can_view_register_files`.

---

## 4) القنوات الخارجية والإشعارات

| القناة | السلوك للسري |
|--------|----------------|
| إشعار داخلي | لا يُرسل لمن لا يجتاز A؛ الجسم يُختزل لرقم/نوع عند الوضع المحرَّر |
| بريد إشعارات النظام | نفس التصفية؛ بلا صفوف موضوع/جهة حساسة |
| بريد/واتساب إرسال الصادر | موضوع محايد؛ **لا مرفقات سرية**؛ بلا نص خطاب كامل |
| `verify.php` / QR | رقم + تسمية محايدة؛ بلا جهة/موضوع حقيقي/خطاب/RSVP عام |

إعداد: `conf_external_notify_mode` = `redacted` (الافتراضي الحازم).

---

## 5) سجل النشاط

الكتابة في قاعدة البيانات كاملة. عند العرض لغير المدير/`admin.logs`: صف مرتبط بكيان سري لا يظهر إن لم يجتز المستخدم طبقة A على ذلك الكيان (`activity_row_visible_to_user`). صفحة سجلات الإدارة (`admin.logs`) ترى التفاصيل كاملة.

---

## 6) تغيّر الأدوار والأقسام

- نقل مستخدم لقسم فيه سري قديم **لا** يفتح له السري التاريخي.
- التغطية/النيابة **لا** تورّث رؤية السري تلقائياً.
- من أُزيل من إسناد مسار يفقد رؤية ذلك السري ما لم تبقَ صفة أخرى (منشئ/CC/صلاحية/مدير).

## 7) أين في الكود؟

| جزء | ملف |
|-----|------|

| بوابات الوصول/الملفات | `config/helpers.php` · `config/archive.php` |

| إرسال خارجي | `config/correspondence_send.php` |
| تحقق عام | `verify.php` |

## 8) مصفوفة تحقق سريعة

1. سري + زميل قسم → لا قائمة ولا فتح.  
2. سري + منشئ → معاملة + مرفقات.  
3. سري + مراجع + B مراجع مسموح → معاملة + مرفقات.  
4. سري + مراجع + B معطّل → معاملة بلا مرفقات.  
5. B اتصالات معطّل + C اتصالات `allow` → مرفقات لهذه فقط.  
6. عادي → سلوك القسم كالسابق.  
7. أرشيف سري + زميل قسم → مخفي.  
8. verify لسري → رقم فقط بلا خطاب.
