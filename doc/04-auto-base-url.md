# 04 — اكتشاف رابط النظام تلقائياً

## المبدأ (مثل نظام الدعوات)

رابط أساس النظام **لا يُحفظ يدوياً** ولا يظهر في صفحة الإعدادات.  
يُستنتج في كل طلب من بيانات السيرفر الحالية، فيعمل على localhost وعلى الدومين الإنتاجي دون تعديل.

## الدوال (في `config/helpers.php`)

| الدالة | الدور |
|--------|------|
| `dms_request_scheme()` | يحدد `http` أو `https` |
| `dms_project_base()` | يحدد مسار المجلد مثل `/dms` |
| `dms_detect_base_url()` | يجمع: بروتوكول + دومين + مسار |
| `base_url($path)` | يبني أي رابط مطلق تحت النظام |

## كيف يُعرف كل جزء؟

### 1) البروتوكول

بالترتيب:

1. رأس البروكسي `HTTP_X_FORWARDED_PROTO` (إن وُجد)
2. أو `HTTPS` من PHP
3. أو المنفذ `443` → `https`
4. وإلا `http`

### 2) اسم الدومين

من `HTTP_HOST` (أو `SERVER_NAME` كاحتياط).

أمثلة:

- محلي: `localhost`
- إنتاج: `example.org`

### 3) مسار المشروع

من `SCRIPT_NAME`:

- `/dms/admin/settings.php` → `/dms`
- `/dms/outgoing/print.php` → `/dms`
- إن وُضع المشروع في جذر الدومين → مسار فارغ

يُستخدم أيضاً مقارنة `DOCUMENT_ROOT` مع مجلد المشروع كاحتياط.

## النتيجة

```
https://example.org/dms
```

ثم مثلاً لـ QR:

```
https://example.org/dms/verify.php?token=...
```

## أين يُستخدم؟

- كل روابط الواجهة والتحويلات
- روابط التحقق في الطباعة (`incoming/print.php`, `outgoing/print.php`)
- صفحة العرض والمرفقات والإحالات
- روابط البريد (إن بُنيت عبر `base_url`)

## ما الذي لا يحدث؟

- لا قراءة `base_url` من `tblsettings` وقت التشغيل
- لا حقل تعديل في الإعدادات
- لا حاجة لتغيير أي شيء بعد الرفع على النت

## ملاحظة عن QR القديمة

رموز QR التي طُبعت سابقاً بروابط `http://localhost/dms/...` تبقى تشير لـ localhost.  
بعد النشر، اطبع المعاملات مجدداً إن احتجت روابط عامة على الإنترنت.
